# 仓桥GEO作战系统 · WorkBuddy 实现方案 V1.0

> 目标：把「1 个品牌事实库 + 1 个 GEO 总控 Agent + 7 个专业 Skill + 复测闭环」落到 Tencent WorkBuddy（v5.3.13）的原生架构上——**学员在课上看到的系统，回去在自己电脑上就能照搭**。
> 依据：WorkBuddy 官方 49 篇文档（已入库 cangqiao/raw/site/workbuddy-official-2026-08-20/）+ 平台自带 5 位 GEO 专家实测分析。

---

## 一、平台自带 5 位 GEO 专家：逐个分析

| 自带专家 | 能力 | 对应我们的 Skill | 局限 |
| --- | --- | --- | --- |
| 品牌GEO可见度诊断师（苍何） | 基建评估、AI收录、竞品对标，输出 AIVO 评分报告 | ≈ S1 诊断 | 通用 AIVO 单分，无六维权重、无 P0/P1/P2 清单、**测完即止无复测** |
| AI搜索与品牌内容专家 | 轻量诊断+竞品差距+内容问题，输出优化策略与执行闭环 | ≈ S1轻量版 + S3策略层 | 「闭环」停在方案文档，不接发布渠道、不回测分数 |
| 竞品分析专家（鹏城信息） | 竞品 SEO/GEO 策略、关键词、外链、AI引用与流量份额 | 我们尚无对应 → 可直接收编为 **S8 竞品Skill** | 单点分析，不与定位/内容联动 |
| 品牌感知分析师 | AI搜索+社媒舆情+热搜三源交叉，叙事一致性与危机预警 | ≈ S7 的「口径一致性」子项 → 可收编为 **S9 舆情Skill** | 监测不回写事实库，预警后没有动作链 |
| GEO内容专家 | 企业知识→定义/FAQ/对比/选型指南/证据结构 | ≈ S3 内容 | 标签偏外贸B2B（询盘云），无八段式/80%标准线约束，**输入不绑定事实库，容易编造** |

**结论：自带专家是「五个不认识彼此的顾问」，能单点干活，但四个系统性缺口决定了它们成不了作战系统：**

1. **无事实库绑定**——每次对话现喂资料，口径无法保证全网统一（推荐五要素第2条直接失守）；
2. **无复测闭环**——诊断完就结束，没有「基线→优化→复测→对比」的验证链；
3. **互不协作**——诊断的结论不会自动变成内容专家的输入；
4. **无交付口径**——输出的是建议文档，不是「发布到公众号草稿箱」「周一自动出周报」的动作。

这四个缺口，恰好就是 WorkBuddy 另外四个原生能力（项目/专家团/自动化/助理）能补上的——**我们的方案不是替代自带专家，而是用系统把它们编进队伍。**

## 二、架构映射：作战系统四层 → WorkBuddy 五个原语

| 作战系统组件 | WorkBuddy 载体 | 实现要点 |
| --- | --- | --- |
| ① 品牌事实库 | **项目（本地文件夹知识库）+ 资料库** | 建 `~/GEO作战/事实库/` 文件夹注册为项目，内放 `品牌事实库.md`（11字段模板）+ 证据文件；WorkBuddy 可直接检索引用；重要版本同步腾讯文档（连接器）供团队协作 |
| ② GEO 总控 Agent | **专家团（Team 型）** | 自建「GEO作战指挥部」专家团：团长按周计划拆解任务→分配给 Skill/成员并行执行→整合成周报。官方定义「团长自动拆解、分配、并行执行、整合交付」正是总控职责 |
| ③ 7 个专业 Skill | **导入本仓库 Skill / 技能市场·创建技能** | 优先导入 `skills/` 下完整目录；S2–S6 的品牌主张只引用稳定事实库，S1/S7 外部观测单独留证且不自动回写事实 |
| ④ 复测闭环 | **自动化（定时任务）** | 两条定时任务：S3 内容日更、S7 每周一复测 20 问出周报并推送小程序/IM |
| 老板两件事 | **助理（IM 遥控，微信/企微/飞书）** | 定标签：语音/文字发给助理即写入事实库待审区；审事实：周报和内容抽检推到老板微信，回复「通过/改」即生效 |

> 课堂一句话：「你们在专家页搜 GEO 看到的 5 个专家，是散兵；我们教你用同一个软件，把散兵编成有指挥部、有弹药库、有周报的部队。」

## 三、7 个 Skill 的 WorkBuddy 落地规格

创建方式优先采用本仓库 `skills/` 下的完整技能目录；平台只能粘贴提示词时，再使用下述精简创建指令。**S2–S6 的品牌主张只准引用稳定且未过期的品牌事实；S1/S7 可以记录外部平台观测，但不得把观测自动当成品牌事实。内容产出按 AI 友好七特征自查并报告达标数（≥5 才交付）。**

| Skill | 创建指令要点（触发→动作→输出） | 复用自带专家？ |
| --- | --- | --- |
| S1 诊断 | 触发「给XX做GEO诊断」→ 建业务语境与冻结查询协议 → 分通道保存真实观测 → 证据校验与质量审计；样本充分时才输出实验性六维评分和建议，默认生成结论优先 HTML 报告 | 使用 `skills/S1-diagnosis/` 完整实现及其 WorkBuddy 专家包 |
| S2 意图词 | 触发「拉意图词」→ 读事实库定位与标签 → 倒推三层意图（攻略/对比/口碑）各20~30词 → 存 `意图词/清单.md`，标注已覆盖/未覆盖 | 否 |
| S3 内容 | 触发「写一篇[意图词]」→ 稳定事实门禁 → 八段式文章（标题→40-80字核心答案→…→FAQ）≥800字≥3证据点 → 存 `内容库/待审/` | 使用 `skills/S3-content/` 完整实现 |
| S4 短视频 | 触发「出[场景]口播脚本」→ 稳定事实门禁 → 大字标题+30–60秒口播+字幕关键词+标签 → 存 `内容库/脚本/` | 使用 `skills/S4-short-video/` 白帽实现 |
| S5 信源发布 | 触发「发布已审内容」→ 只取人工已审稿 → 公众号/官网/百科等适配版与发布清单，可选 PDF → 存 `发布包/`；实际发布另行确认 | 使用 `skills/S5-publishing/` 完整实现 |
| S6 官网地基 | 触发「查官网地基」或「生成官网」→ 7 条体检或基于稳定事实生成单文件 HTML → 运行占位/JSON-LD/FAQ 校验 → 输出待审页面 | 使用 `skills/S6-website-foundation/` 完整实现 |
| S7 复测监测 | 触发「跑周测」→ 同一套 20 问复测 → 更新 `监测表.md`（问题×平台×周：提及/推荐/引用/准确）→ 与基线对比出趋势 | 可编入「品牌感知分析师」做舆情侧信号 |
| S8 竞品（扩展） | 直接召唤自带「竞品分析专家」，产出存 `竞品/`，供 S2/S3 参考 | **全量复用** |

## 四、总控专家团「GEO作战指挥部」设计

- **团长提示词（核心）**：「你是 GEO 作战总控。接到任务先读《品牌事实库.md》和《监测表.md》，按 28 天路线图判断当前周（1地基/2内容/3权威/4复测），把任务拆给对应 Skill 并行执行，校验产出是否达 80% 标准线，最后汇总为《周报》：本周发了什么→哪些被 AI 收录→分数动没动→下周 P0 三件事。所有内容不得超出事实库，待审事项单独列出等老板确认。」
- **成员**：S1~S8 Skill + 自带「竞品分析专家」「品牌感知分析师」；
- **注意**：官方提示专家团积分消耗为单专家数倍——课堂上讲清成本策略：日常单点任务直接叫 Skill，只有周计划和周报用专家团。

## 五、复测闭环：两条自动化任务

| 任务 | 定时 | 提示词要点 | 输出 |
| --- | --- | --- | --- |
| GEO内容日更 | 每工作日 09:00 | 「从意图词清单取 1 个未覆盖词，调用 S3 写八段式文章存待审区，并推送摘要到小程序」 | 待审文章 + 小程序提醒 |
| GEO周测周报 | 每周一 08:30 | 「调用 S7 跑 20 问复测，更新监测表，调用总控出周报，推送小程序/微信」 | 周报 + 趋势对比 |

配合**助理**：老板在微信收到待审摘要，回「通过」→ S5 进入发布流程；回修改意见 → 回写事实库或退回 S3。**这就是「老板两件事」的产品形态：定标签（发语音给助理）、审事实（微信里点头）。**

## 六、搭建顺序（半天上线）

1. **第 1 步（30分钟）建事实库**：新建 `~/GEO作战/` 文件夹（事实库/诊断报告/意图词/内容库/发布包/竞品/监测表），填 11 字段品牌事实库，WorkBuddy 注册为项目；
2. **第 2 步（1.5小时）建 7 个 Skill**：按第三节创建指令逐个创建（每个约 10 分钟，创建后用一条真实任务调试）；
3. **第 3 步（1小时）建总控与闭环**：创建「GEO作战指挥部」专家团 → 配两条自动化任务 → 绑定微信助理 → 跑一次全流程（S1 基线诊断 → 总控出第一周计划）。

## 七、课程与交付中的用法

- **课堂（工具篇 M05）**：先让学员搜「GEO」看 5 个自带专家（人人可复现，建立「工具不难」认知）→ 再演示我们的作战系统跑通一条「诊断→写文→待审→周报」链（拉开差距：散兵 vs 部队）；
- **学员分层**：免费学员 → 教用自带专家单点起步；训练营/陪跑学员 → 交付整套 Skill 包（技能包可导出导入）+ 专家团配置 + 自动化模板，半天照搭；
- **交付阶梯映射**：按 S1→地基→全系统 分阶段上线（形态示例）；
- **攻防话术**：「WorkBuddy 自带的 GEO 专家能不能用？能，我们课上就教——但五个专家互不认识、不带你的事实库、测完不复测。我们教的是把它们编成部队的方法，这个方法本身就是课程价值。」

## 八、风险与边界

- 自带专家能力与标签（如询盘云）可能随平台更新变动，课前一周复核截图；
- 专家团积分成本需在课堂明示（官方有提醒条款），给出「Skill 日常用、专家团周会用」的省钱策略；
- 自动发布类动作保留人工审核环节（白帽红线：AI 内容必须人工审核后发布），演示时强调待审区设计；
- WorkBuddy 项目/技能均在本地，学员换电脑需导出技能包——交付时附迁移说明。
