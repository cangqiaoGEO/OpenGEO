# GEO 意图词

## 不可违反的约束

- 只引用品牌事实库中 `status: stable` 且 `stale_after` 未过期的概念；不得用模板、示例库或外部搜索补全客户事实。
- 将没有稳定事实支撑的信息列为“待确认”，不得写进问题、覆盖结论或品牌表述。
- 将新清单写为 `draft`；不得覆盖现有的 `stable` 清单。
- 在交付前列出引用的概念文件，并完成 AI 友好七特征自检；至少 5 项达标才交付。

## 执行流程

### 1. 确认输入与输出位置

要求调用方提供品牌事实库根目录。根目录必须包含 `positioning.md` 和 `audience.md`；涉及品牌名时还必须有可引用的 `identity.md`。

默认输出为 `<事实库>/intent-words/清单.md`。如目标文件已是 `stable`，保留原文件，改写为 `<事实库>/intent-words/清单-YYYY-MM-DD.md`，并在回复中说明原因。

不要用 `brand-facts/template/` 或 `brand-facts/examples/` 生成客户交付物，除非用户明确要求演示或测试。

### 2. 先通过事实门禁

运行下列命令，替换为实际路径：

```bash
python3 scripts/validate_intent_words.py inspect --facts-dir <事实库目录>
```

只有命令成功时才继续。发生以下任一情况时，停止生成并列出待补项：文件缺失、`status` 不是 `stable`、`stale_after` 已过期，或 YAML frontmatter 不完整。

随后阅读 `positioning.md`、`audience.md`，以及与问题相关的可引用 `identity.md`、`products/`、`boundaries.md`、`faq.md`。使用 [事实库约定](references/fact-library-contract.md) 判断文件是否可引用。

### 3. 盘点已有内容

要求调用方指定内容库目录；没有目录时，将所有条目标记为“未覆盖”，不得臆测覆盖状态。逐篇检查标题、摘要、FAQ 和正文，使用以下标签：

- `已覆盖`：现有内容直接回答该问题，并在表中给出相对文件路径。
- `部分覆盖`：现有内容只回答部分决策点；给出路径和缺口。
- `未覆盖`：未找到可验证的对应内容。

不要把标题相似、未审稿、或只出现品牌名的内容判为“已覆盖”。

### 4. 生成三层问题

每层生成 20–30 条自然语言的用户提问，总计 60–90 条。使用 [输出模板](references/output-template.md) 的表格和字段，保持问题去重、可回答、可用于后续内容生产。

- **场景攻略层**：从目标客户的场景、痛点、选择标准、方法和避坑问题出发；优先非品牌问题。
- **品牌对比层**：围绕品类、方案、交付方式与选择标准比较；只有事实库明确记录时才使用竞品名称或具体对比事实。
- **口碑验证层**：围绕已确认的品牌名、资质、交付、评价、边界和联系入口设计核验问题；不制造口碑、案例、资质或价格前提。

把问题写成提问而非答案或广告语。品牌名、产品名、地域、服务能力等专有事实必须逐项可追溯到引用文件。信息不足时使用更通用的问法，或在“待确认”中提出需要老板确认的标签。

### 5. 写入并校验

写入清单后运行：

```bash
python3 scripts/validate_intent_words.py validate --facts-dir <事实库目录> --output <清单文件>
```

修复所有错误后再交付。校验器检查三层各 20–30 条、覆盖状态、必需引用文件和七特征自检；它不替代事实判断和人工审核。

### 6. 交付说明

回复中只报告：输出路径、各层条数、覆盖状态汇总、待确认事项、引用概念文件、七特征达标数。将“优先写什么”限定为内容生产建议，不承诺排名、收录或转化结果。
