# 品牌事实库约定

## 输入边界

每个 Skill 的 `SKILL.md` 定义本任务所需概念文件。常见文件职责如下：

| 文件 | 用途 |
| --- | --- |
| `identity.md` | 品牌全称、简称、地点与统一身份表述 |
| `positioning.md` | 品类、定位、核心标签和差异化边界 |
| `audience.md` | 客群、场景和决策问题 |
| `products/` | 产品、能力、价格、交付和适用范围 |
| `boundaries.md` | 不适用场景与明确限制 |
| `faq.md` | 已确认问题与答案 |
| `channels.md` | 联系、预约、试用等真实转化入口 |
| `evidence/` | 案例、资质、数据、评价和公开来源证据 |

缺少任务必需文件时停止相关输出，列为待补项；不得用模板、模型记忆或外部搜索替代。

## 引用资格

概念文件只有同时满足以下条件才能引用：

1. YAML frontmatter 包含 `status: stable`；
2. 没有 `stale_after`，或该日期不早于本次运行日期；
3. 表述与正文直接相关，且没有超出来源支持范围；
4. Evidence 类主张能解析到有效的 `sources` 条目。

`draft`、`deprecated`、没有 frontmatter、已过期或来源失效的文件都不可引用。将它们列为待补项，不改写、猜测或静默降级使用。

## 事实、证据与观测

- 品牌事实描述“品牌确认什么”；案例与来源描述“什么证据支持该表述”；平台观测只描述“本次看到了什么”。三者不得互相冒充。
- 品牌自有材料可以支撑身份、产品与边界，但不能自动成为独立客户、专家或媒体背书。
- 任何数字、价格、客户结果、资质、团队经历、评价和效果表述都要逐项追溯，不能从相邻事实推断。
- 外部材料需先经 ingest 与人工审核成为稳定概念，内容 Skill 才能使用。

## 版本与审核

新产物默认写为 `draft` 或该 Skill 定义的待审状态。已有 `stable` 或人工已审文件不得覆盖；创建日期版或递增版本。只有负责人可以把内容提升为 `stable`、修改 `verified`，或授权实际发布与部署。
