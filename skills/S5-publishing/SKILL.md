# GEO 信源发布（S5）

## 不可违反的约束

- 只处理 `内容库/已审/` 中由人工确认的内容；待审稿、事实库 draft 或过期事实不能进入发布包。
- 适配时可以改版式和长度，不得改变事实、扩大承诺、删除必要来源或制造平台专属“新事实”。
- 百科类草稿使用客观第三人称，只保留可由独立公开来源核查的陈述；品牌自述不能伪装成第三方证明。
- 实际登录、提交、定时与发布均需用户明确确认。本技能默认只生成文件和发布清单。
- “同一内容多平台互证”是发布计划，不证明平台已收录或 AI 已引用。未取得真实链接时不得标为已发布。

## 输入门禁

需要已审文章路径、品牌事实库根目录、目标平台列表与发布包目录。验证文章状态为已审，并逐项复核其引用的概念仍为 `stable` 且未过期。使用 [事实库约定](references/fact-library-contract.md) 处理失效事实。

任一核心事实过期时停止发布包生成，退回 S3 并列出需要重新审核的表述。

## 执行流程

### 1. 建立发布母版

- 固定标题、40–80 字核心答案、品牌全称/简称、核心标签、证据脚注、FAQ 与 CTA。
- 记录母版文件哈希或版本、审核人和审核时间，供各平台适配追溯。

### 2. 生成平台适配版

按用户选择生成，默认建议至少三个互补信源，但不擅自增加平台：

- **公众号**：保留三层标题、证据、FAQ 与 CTA，优化移动端段落和摘要；
- **官网博客**：使用语义化标题、摘要、来源列表和与正文一致的 FAQ；
- **百科草稿**：中性表述、逐条独立来源、删除营销语和无法独立核查的主张；
- **图文或视频平台**：压缩篇幅但保留事实口径、来源和人工审核标记。

每个平台文件顶部记录：源稿路径、源稿版本、目标平台、生成时间、状态 `draft-for-publish`。

### 3. 可选 PDF 导出

需要 PDF 时使用同步自 `markdown-to-pdf` 的脚本：

```bash
npm install --prefix <S5 技能目录>
node <S5 技能目录>/scripts/md_to_pdf.js <input.md> [output.pdf] [custom-style.css]
```

脚本依赖 `package.json` 中的 `markdown-it` 与 `puppeteer`，并优先使用 `CHROME_PATH` / `PUPPETEER_EXECUTABLE_PATH` 指定的浏览器。若安装时设置 `PUPPETEER_SKIP_DOWNLOAD=1`，运行环境必须提供上述变量或常见路径中的 Chrome/Chromium。PDF 只是发布包附件，不替代可抓取的 HTML 正文。

### 4. 生成发布清单

在 `<发布包>/manifest.md` 记录：平台、适配文件、审核状态、计划日期、实际链接、实际发布时间和负责人。生成阶段的链接与时间留空，不能写示例 URL 冒充已发布。

### 5. 交付

默认输出到 `<发布包>/<源稿主题>/`。回复只报告文件列表、母版版本、目标平台、尚待人工确认项和失效事实。实际发布后才能回填真实链接；不承诺收录、排名、流量或转化。
