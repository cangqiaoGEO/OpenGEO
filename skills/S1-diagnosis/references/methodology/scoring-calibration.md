## Brand GEO 评分校准与标准化路线

### 一、什么叫“科学定型”

一个公式写进代码、测试全部通过，只能证明实现稳定，不能证明测量正确

本项目只有同时建立以下证据，才可以从“工程评分框架”升级为“经过验证的测量工具”：

- 构念定义明确
- 内容覆盖充分
- 标注具有一致性
- 重复测量误差可量化
- 分数结构符合理论预期
- 与外部结果存在可解释关系
- 对行业和品牌变化具有响应性
- 独立团队可以复现
- 版本、数据和不确定性可审计

在达到外部复现之前，README 和报告均不得使用“权威标准”“行业标准”或“科学定型”等表述

### 二、成熟度等级

| 等级 | 名称 | 发布含义 |
|---|---|---|
| M0 | 概念草案 | 只有问题定义和候选指标，不输出正式总分 |
| M1 | 理论支撑 | 构念有外部依据，操作化和权重仍为启发式，可输出实验性分项 |
| M2 | 内部验证 | 完成专家内容效度、标注一致性和重复性实验，可输出带不确定性的内部基准 |
| M3 | 多行业校准 | 在多个行业和品牌样本上完成结构、敏感性和阈值校准，可发布版本化评分模型 |
| M4 | 外部验证 | 独立团队或数据集复现主要结论，可称经过外部验证的 GEO 评分标准候选 |
| M5 | 标准治理 | 具有公开规范、变更治理、参考实现、测试集和持续复核机制，才可讨论科学定型或行业标准 |

当前版本为 `M1`，不是 `M4` 或 `M5`

### 三、第一阶段：定义测量对象

为每个维度建立指标卡：

- 构念名称和业务含义
- 与相邻构念的边界
- 正例、反例和不适用情况
- 可观测变量
- 标注单位和规则
- 预期误差来源
- 当前证据等级
- 允许和禁止的结论

先完成构念独立性审查，避免可见度、推荐度、情感和覆盖度重复计算同一现象

### 四、第二阶段：建立校准数据集

数据集应采用分层设计，而不是继续追加单一行业案例：

- 多行业：高决策成本 B2B、消费品牌、本地服务、教育、医疗等
- 多品牌：头部、中腰部、区域品牌、新品牌和同名高风险品牌
- 多问题：发现、选择、解决方案、比较、风险和事实核验
- 多平台：不同生成式引擎、模型、模式和搜索能力
- 多时间：短期重复、跨周和跨模型版本
- 多标注者：领域专家、普通目标用户和受训标注者

数据集必须保留原始回答、来源、截图、运行配置、实体规范化结果和标注分歧，不得只保存最终分数

### 五、第三阶段：验证内容效度

由跨角色专家组评价每个指标是否：

- 与 GEO 目标相关
- 覆盖充分
- 表述清楚
- 能被稳定观察
- 适用于哪些行业
- 需要哪些行业适配项

建议至少包括：信息检索或生成式搜索研究者、品牌或内容策略人员、行业专家、数据测量人员和目标用户代表

专家意见应保存原始评分、分歧和修改记录；Delphi 或专家共识可以用于形成候选指标，但不能替代后续数据验证

### 六、第四阶段：验证标注信度

同一批原始回答由至少两名独立标注者完成标注，分别计算：

- 分类变量的一致率和 `Cohen's kappa` 或 `Krippendorff's alpha`
- 连续或等级结果的组内相关系数
- 分歧集中在哪些查询、行业和状态
- 规则修改前后的提升

低一致性的指标必须先修订定义和示例，不能直接通过扩大样本掩盖

### 七、第五阶段：测量重复性和不确定性

对同一品牌、查询、平台和模式执行重复运行，至少分别估计：

- 同条件短期重复性
- 跨时间稳定性
- 跨模型版本变异
- 跨平台差异
- 浏览器与 API 通道差异
- Prompt 轻微变体敏感性

正式结果不应只给一个点估计，应同时报告样本数、分布、置信区间或适当的不确定性范围

现有三平台各三次实验只证明输出存在波动，是验证计划的先导样本，不能用于确定正式重复次数或误差范围

### 八、第六阶段：验证效度

#### 8.1 构念效度

检验理论上相关的指标是否相关、理论上不同的指标是否可区分

例如：品牌出现位置应与可见度相关，但不应自动等同于推荐度；结构化官网可能与引用概率相关，但不应直接等同于 AI 可见度

#### 8.2 收敛与区分效度

与独立人工评价、其他 GEO 测量方法或外部平台观测比较，同时确认结果不会退化成普通搜索排名、内容数量或品牌规模代理

#### 8.3 预测效度

在不参与建模的查询、平台和未来时间窗口中检验：当前分数是否能预测品牌后续进入答案、被引用或被推荐的概率

#### 8.4 响应性

对官网事实页、第三方权威内容或实体一致性做受控改动，检验评分能否在合理时间内检测到变化，同时排除平台自然波动

### 九、第七阶段：校准权重和阈值

权重不能仅依赖专家直觉，也不能为了产生整数等级而倒推

建议顺序：

1. 先长期报告六个分项，不急于生成总分
2. 使用专家判断形成候选权重范围
3. 使用真实结果检验各维度对目标结果的解释和预测能力
4. 执行敏感性分析，检查权重小幅变化是否导致品牌等级大幅跳变
5. 检查不同行业是否需要不同权重配置，而不是强求一套全球权重
6. 使用保留集确定阈值，再用独立样本验证
7. 阈值无法稳定时，继续报告分项和区间，不发布字母等级

最终权重必须记录数据版本、优化目标、估计方法、置信区间、适用行业和失效条件

### 十、第八阶段：外部验证与标准治理

达到标准候选至少需要：

- 公开指标规范和版本历史
- 可公开或受控访问的基准数据集
- 独立参考实现和一致性测试
- 至少一次非原作者团队复现
- 行业适配规范和最小样本要求
- 已知局限、偏差和不适用场景
- 模型或平台改版后的复核机制
- 弃用和迁移策略

外部验证失败时应降低成熟度等级，不得只更新文案维持“标准”称号

### 十一、研究验证阶段

#### 研究阶段 E1：方法学底座

- 理论来源登记
- 指标卡与证据等级
- 三层领域模型
- 双协议架构
- `MeasurementPlan` 和指标配置版本设计

#### 研究阶段 E2：契约迁移

- 新增 `IndustryProfile`
- 新增 `BrandEntityProfile`
- 新增 `ContentFoundationProtocol`
- 查询协议增加产品、场景和行业因素引用
- 证据包增加探针完成状态和原始证据引用

#### 研究阶段 E3：测量可靠性

- 多标注者一致性工具
- 正式重复运行投影规则
- 不确定性输出
- 实体污染率和行业覆盖率

#### 研究阶段 E4：校准研究

- 多行业品牌数据集
- 专家内容效度研究
- 权重敏感性和结构分析
- 阈值校准与保留集验证

#### 研究阶段 E5：外部验证

- 第三方复现
- 公开规范、参考数据和模型卡
- 标准候选版本发布

架构、代码和单元测试可以由项目内部完成；科学定型必须依赖持续采样、专家评审和独立复现，不能通过一次代码迭代完成
