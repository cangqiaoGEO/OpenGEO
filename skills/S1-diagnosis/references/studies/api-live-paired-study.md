### 四、DeepSeek API 重复实验

三个请求均使用：

```text
model              deepseek-v4-flash
thinking_mode      disabled
search_mode        none
temperature        0.2
max_output_tokens  2048
```

| 轮次 | 正文字数 | 引用数 | 总 Token | 完成原因 |
|---|---:|---:|---:|---|
| 1 | 2335 | 0 | 1329 | stop |
| 2 | 3015 | 0 | 1717 | stop |
| 3 | 2660 | 0 | 1516 | stop |

稳定性结果：

| 指标 | 数值 |
|---|---:|
| 回答长度均值 | 2670 |
| 回答长度变异系数 | 0.1040 |
| 提及实体 Jaccard | 0.3433 |
| 推荐实体 Jaccard | 0.3433 |
| 首位实体一致率 | 1.0000 |
| 搜索执行率 | 不适用 |
| URL Jaccard | 不适用 |

三次回答首位实体均规范化为龙芯，但完整方案实体集合的重合度较低

第三轮同时出现“百科荣创”和“百科融创”，事实抽检确认这属于高风险实体冲突，不能把两者自动合并为别名，也不能不经核验地当作两个独立推荐对象

### 五、DeepSeek API 与消费者网页差异

两侧使用同一查询且各重复 3 次，但消费者网页执行原生搜索，API 没有原生搜索，消费者网页模型 ID 也不可验证，因此只能做分维度差异描述

| 维度 | 消费者网页 | 官方 API | API 相对变化 |
|---|---:|---:|---:|
| 回答长度均值 | 1372 | 2670 | +1298，约 1.9461 倍 |
| 平均结构化引用数 | 11.67 | 0 | -11.67 |
| 搜索执行率 | 100% | 不适用 | 能力不相同 |
| 推荐出现率 | 66.67% | 100% | +33.33 个百分点 |
| 首位实体众数 | 百科荣创 | 龙芯 | 不相同 |

集合差异：

| 指标 | 数值 |
|---|---:|
| 提及实体并集 Jaccard | 0.0323 |
| 稳定核心实体 Jaccard | 0.1429 |
| 推荐实体并集 Jaccard | 0.0333 |

这组结果已经证明 API 不能等同于消费者 App，但不能把差异全部归因于“API 接口”本身，模型不可验证和搜索能力不同也是主要变量

### 八、工程改动

- API 采集器增加严格 TLS CA 选择逻辑，不关闭证书验证
- `RepeatedObservationExperiment` 同时支持 `official_app_browser` 与 `official_api`
- 无搜索 API 的搜索执行率和 URL Jaccard 输出 `null`，不伪装成 0 或 100%
- 新增 `channel_compare.py`，按维度比较两个通道，不生成虚假总差异分
- API 原始请求、响应、实验包和比较结果保存在 Git 忽略的 `skills/S1-diagnosis/work/api-artifacts/`

### 九、正式品牌 GEO 诊断的剩余输入

标准查询协议要求覆盖品类推荐、解决方案、品牌直达和品牌对比四类问题

当前示例研究包中的“示例教育”和“示例竞品”是占位符，不能提交给外部模型并据此形成真实品牌结论

进入正式诊断前需要提供真实目标品牌和至少一个真实竞品，再重新建立并冻结该品牌的查询协议；豆包与千问可以后续单独恢复，不需要重跑本次已完成的 DeepSeek 资格测试
