## 国内三平台消费者网页联调基线

### 一、基线目的

本文是历史实验快照，记录 2026-08-20 对豆包、千问和 DeepSeek 消费者网页端的首轮真实采集结果，不代表当前平台状态或当前项目待办

本轮只验收浏览器采集能力、联网执行证明、正文提取、来源提取、隐私裁剪截图和契约校验，不评价任何品牌，也不形成三平台准确率排名

三个平台的运行模式不同，因此本轮结果不能直接比较得分：

- 豆包使用快速模式，页面自动执行联网搜索
- 千问使用登录后页面当前选中的思考研究模式
- DeepSeek 使用快速模式，深度思考关闭，智能搜索开启

### 二、统一探针

三个平台使用同一条脱敏查询：

> 职业院校建设嵌入式实训室时，国内有哪些值得考虑的解决方案？

对应示例协议 `protocol-example-education` 的 `q-category`

### 三、实际采集结果

| 平台 | 消费者模式 | 联网执行证据 | 正文字数 | 页面报告来源 | 可直接解析 URL | 契约结果 |
|---|---|---|---:|---:|---:|---|
| 豆包 | 快速 | 搜索 4 个关键词 | 2560 | 20 | 20 | 通过 |
| 千问 | Qwen3.7-千问、思考研究 | 搜索 6 个关键词 | 2379 | 23 | 2 | 通过 |
| DeepSeek | 快速、深度思考关闭、智能搜索开启 | 已阅读 12 个网页 | 971 | 12 | 12 | 通过 |

千问的来源面板完整展示 23 条标题和域名，但当前 DOM 只直接暴露 2 个 URL，因此：

- `citations` 只保存 2 个真实 URL
- 23 条面板文本保存在脱敏后的 `raw_payload.source_panel_text`
- 不根据域名和标题拼接或猜测 URL

### 四、选择器校准结果

以下选择器只代表 2026-08-20 的页面结构，平台改版后必须重新核验

#### 4.1 豆包

```text
输入区      [contenteditable="true"][role="textbox"]
提交        Enter
回答区      [aria-label="doc_editor"] .md-box-root
来源入口    精确文本：搜索 4 个关键词，参考 20 篇资料
```

#### 4.2 千问

```text
输入区      [data-slate-editor="true"][role="textbox"]
提交按钮    [aria-label="发送消息"]
回答区      .qk-markdown-complete
来源入口    精确文本：23篇来源
```

#### 4.3 DeepSeek

```text
输入区      textarea[name="search"]
提交        Enter
回答区      .ds-assistant-message-main-content
搜索开关    文本为智能搜索，aria-pressed=true
来源入口    精确文本：12 个网页
```

来源面板的内部 class 属于动态实现细节，不作为长期稳定选择器

### 五、隐私与证据处理

- 登录、验证码和账号授权全部由用户本人完成
- 请求和响应文件保存在被 Git 忽略的 `skills/S1-diagnosis/work/browser-artifacts/`
- 截图只截取回答或来源主区域，不包含侧栏对话历史与账号标识
- 原始响应不保存 Cookie、Local Storage、Authorization Header 或页面完整 HTML
- 三个平台的对话记录会保留在用户对应账号中，这是消费者网页实测产生的正常平台状态

### 六、阶段结论

D3 已证明三个头部消费者网页都能够完成低频、人工授权、可追溯的浏览器采集

消费者网页单次采样限制已由 D4 三次重复实验补充，结果见 `browser-repeatability-study.md`

当前仍不能回答 API 与 App 相差多少，因为尚未使用 API 做同查询配对

进入差异测量前需要：

1. 使用已冻结模式完成 API 同题采集
2. 每个平台 API 通道至少重复 3 次
3. 分别完成 API 回答的语义标注
4. 独立计算浏览器与 API 得分
5. 再计算出现、推荐、引用、覆盖、情感和综合分差
