## Brand GEO Audit 模块渐进式路线

### 一、路线原则

项目同时维护三条不同时间尺度的目标：

- 当前基线：保持 v2 可运行、可复算、可回归
- 短期产品：形成 WorkBuddy GEO 诊断专家 MVP
- 长期研究：积累多行业数据并逐步验证测量方法

三条路线不能混写成一次性 v3 重构

### 二、阶段 R0：基线整理与目标冻结

目标：让当前实现、短期产品和长期路线各有唯一说明位置

产出：

- WorkBuddy 诊断专家产品目标
- 当前 v2 规格
- 文档分类和责任边界
- 案例隔离原则
- 报告模式决策
- 当前缺口登记

验收：冷读者能够区分已经实现、准备实现和未来验证三种状态

### 三、阶段 R1：诊断 MVP 契约

状态：已完成

采用兼容式扩展，不立即破坏 v2：

```text
DiagnosticRun
  -> BrandEntityProfile
  -> IndustryProfile
  -> MeasurementPlan
       -> QueryProtocol
       -> ContentFoundationProtocol
  -> existing v2 evidence, score and audit objects
```

优先实现：

1. `DiagnosticRun` 运行清单和阶段状态
2. `BrandEntityProfile` 最小实体卡
3. `IndustryProfile` 轻量行业适配卡
4. `ContentFoundationProtocol` 独立内容探针协议
5. `diagnostic` 与 `experimental_score` 报告模式

已冻结的实现决策：

- 现有 v2 研究包保持不变，R1 新对象放入独立诊断包，由 `DiagnosticRun` 引用
- `diagnostic` 模式完全隐藏总分和等级，`experimental_score` 仅用于内部研究
- 行业卡只保留经营范围、服务方式、市场特征和有证据的决策因素
- 真实客户数据留在 `work/` 或受控数据集，公开示例使用合成数据

### 四、阶段 R2：真实品牌试点

状态：已完成受控工作流验证

选择 3–5 个差异明显的品牌进行受控试点，不把任何单一案例升级为产品默认

试点应覆盖：

- 高决策成本 B2B 品牌
- 消费品牌
- 区域服务品牌
- 本地中小或微型门店，覆盖品牌别名、地域高价值查询和消费者 App 联网搜索
- 同名或实体关系复杂品牌

试点主要验证工作流、实体识别、行业因素覆盖、标注可执行性和下游交接，不用于校准正式权重

已验证的通用能力：

- 3 个可删除真实案例覆盖五类试点组合
- 消费者 App 冻结查询、三次重复采集与原始证据留存
- 规范品牌、已核验关联实体、同品类其他实体和缺席状态分离
- 重复性描述指标独立于 GEO 评分
- 诊断事实、推断、未知、反证、证据缺口和规划问题的独立交接契约

受控协议见 [R2_PILOT_PROTOCOL.md](R2_PILOT_PROTOCOL.md)

### 五、阶段 R3：测量可靠性

- 多标注者一致性
- 重复运行投影规则
- 不确定性输出
- 实体污染率
- 行业因素覆盖率
- Schema 与运行时校验器符合性测试

进入 R3 前先发布 WorkBuddy MVP：用查询族和表达变体替代单题代表整体诊断，默认生成精简客户报告和机器汇总，通过真实运行持续积累后续校准数据

### 六、阶段 R4：多行业校准

- 建立分层数据集
- 专家内容效度评审
- 权重敏感性分析
- 阈值和保留集验证
- 行业配置差异分析

### 七、阶段 R5：外部验证与治理

- 独立团队复现
- 公开或受控基准数据集
- 参考实现与一致性测试
- 版本治理、弃用和迁移规则

达到这一阶段之前，不把当前评分称为行业标准或科学定型标准

### 八、当前决策门

进入 R3 前需要冻结可靠性方案：

- 第二标注者及盲审、分歧裁决规则
- 重复运行如何投影为诊断结论，不把描述性稳定性直接变成分数
- 实体污染率、行业因素覆盖率和不确定性输出定义
- WorkBuddy 实际提供的 Tool、文件交付与下游规划交接能力
