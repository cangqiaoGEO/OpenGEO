# Brand GEO Audit（品牌 GEO 诊断）

对给定品牌关键词执行一次完整的生成式引擎优化（GEO）诊断：量化品牌在主流
AI 引擎答案中的表现，输出具体指标值与可执行的改进建议。

## Overview

GEO 指优化品牌在生成式 AI 引擎答案中的可见度与推荐概率。本技能通过
"用户提供真实查询结果 + WebSearch 模拟检索"双通道收集数据，按统一指标体系
（见 `references/geo-metrics.md`）计算得分，产出 HTML 诊断报告。

最终交付物：
1. 对话内的诊断结论摘要（总分、等级、最强/最弱维度、Top 建议）
2. 一份完整的 HTML 诊断报告（雷达图、维度得分、引擎对比矩阵、指标明细、建议清单）

## Workflow Decision Tree

- 用户只给了品牌关键词 → 执行完整诊断流程（下面 5 步）
- 用户给了品牌关键词 + 某个/多个 AI 引擎的问答文本 → 按该引擎填充分数，跳过对应数据收集
- 用户要求跟踪/复查（此前诊断过）→ 快速模式：只更新可见度与情感两项，输出变化对比
- 用户仅问概念（"什么是 GEO"）→ 不执行诊断，直接解释概念

## Step 1: 确认品牌与诊断范围

1. 从用户请求中提取品牌关键词（品牌名，可含品类词，如"腾讯云"、"某品牌 智能手表"）。
2. 若无明确品牌，向用户确认目标品牌与品类。
3. 确定测试查询集（5-8 条为宜，覆盖 4 类问题）：
   - 品类推荐型："最好的{品类}是什么？"
   - 品牌对比型："{品牌}和{竞品}哪个好？"
   - 解决方案型："{品类}应该怎么选？/ 选{品类}注意什么？"
   - 品牌直达型："{品牌}怎么样？{品牌}值得买吗？"
4. 确定引擎集合：默认 3-5 个（国际：ChatGPT、Perplexity；国内：DeepSeek、豆包、Kimi；有需要再加 Gemini、Copilot、文心一言）。
5. 如需竞品对比，让用户指定 1-3 个竞品品牌，或根据品类自动推断主流竞品。

## Step 2: 数据收集（双通道）

### 通道 A：用户提供真实查询结果（优先，准确性最高）

向用户提供标准查询话术，请其将各引擎的回答粘贴回来（或提供截图/描述）：

> 请在以下引擎中逐一提问并复制回答：
> 1. {查询 1}  2. {查询 2}  3. ...
> 引擎：ChatGPT / Perplexity / DeepSeek / 豆包 / Kimi …

若用户已提供文本，跳过此步。若用户无法提供，仅使用通道 B，并在报告中标注
"基于公开可索引内容模拟评估，非实时引擎实测"。

### 通道 B：WebSearch 模拟检索（自动执行）

用 WebSearch 对每条测试查询 + 品牌词执行检索，评估品牌在可索引内容生态中的表现，
推断其在 AI 引擎中的引用潜力。每条查询至少 1 次搜索，检查：
- 品牌官网 / 官方内容是否出现且排位
- 百科、权威媒体、评测、社媒内容的有无与数量
- 品牌核心信息（简介、卖点、产品线、价格、口碑、动态）在搜索结果中的覆盖
- 竞品相关内容量对比

同时用 WebFetch 抽查品牌官网与百科条目，确认结构化内容（FAQ、schema.org）与信息准确性。

### 数据落盘

将收集结果整理为标准 JSON（结构见 `scripts/geo_score.py` 文档字符串），保存到
工作目录 `geo_data_<brand>.json`。字段含义与取值见 `references/geo-metrics.md`。

## Step 3: 计算指标

运行评分脚本（须使用托管 Python）：

```bash
python3 <skill_dir>/scripts/geo_score.py geo_data_<brand>.json
```

脚本输出 JSON 包含：各维度得分、综合得分、等级（S/A/B/C/D）、薄弱维度、分引擎明细。
若通道 A 部分引擎缺失，脚本对缺失引擎的查询不计算；综合得分仅基于已收集查询。

得分与等级解读规则：
- 综合得分 ≥60 为合格；薄弱维度判定标准为维度得分 <60。
- 用 `weak_dimensions` 定位需要优先改进的维度。

## Step 4: 生成改进建议

按 `references/geo-metrics.md` 第 5 节的规则与通用建议库，为每个薄弱维度生成建议：
- 每条建议含：行动项（怎么做）、预期效果（影响哪个指标）、衡量方式（如何验证）。
- 按 P0（1-2 周）/ P1（1-2 月）/ P2（持续）分级。
- 额外补充 2-3 条基于引擎对比矩阵的差异化建议（如某引擎完全不可见 → 针对该引擎
  内容偏好补充素材）。

## Step 5: 生成建议数据与 HTML 报告

### 5.1 生成建议 JSON

按 `references/geo-metrics.md` 第 5 节规则，为每个薄弱维度生成建议；另据引擎对比矩阵
补充 2-3 条差异化建议。将建议写入 `geo_data_<brand>.json` 的 `suggestions` 字段：

```json
{"suggestions": [
  {"priority": "P0", "dimension": "visibility", "action": "…",
   "effect": "提升品牌在 AI 答案中的出现率", "measure": "下月复查出现率提升至 ≥60%"}
]}
```

每条建议含行动项（怎么做）、预期效果（影响哪个指标）、衡量方式（如何验证）。

### 5.2 生成 HTML 报告

运行报告生成脚本（须使用托管 Python）：

```bash
python3 <skill_dir>/scripts/geo_report.py geo_data_<brand>.json geo_result_<brand>.json -o <brand>_geo_audit_report.html
```

脚本自动产出浅色主题中文单文件报告，包含：综合得分与等级徽章、六维雷达图、
维度进度条明细、引擎对比矩阵、内容基础评估、逐条查询明细、P0/P1/P2 建议卡片、
数据来源脚注。若 `geo_data_<brand>.json` 缺少 `suggestions` 或 `source_note` 字段，
报告相应位置会显示占位提示，此时应先补齐数据再生成。

### 5.3 交付

- 用 present_files 展示 HTML 报告
- 在对话中给出摘要：总分、等级、最强与最弱维度、Top 3 建议（精简列出，不冗长）

## 通用规则与注意事项

- 若用户仅给关键词未给引擎，默认覆盖 ChatGPT、Perplexity、DeepSeek、豆包、Kimi。
- 通道 B 属于模拟评估，报告中必须注明局限；有通道 A 数据时以通道 A 为准。
- 情感、覆盖度等存在主观性的判断，在明细表中标注判断依据，供用户复核。
- 竞品对比仅当用户要求或品类需要时进行；对比结论须基于同一组查询。
- 报告的浅色主题与汉字编码需在生成时保证（避免乱码）。
- 诊断输出仅作为参考，不构成任何投资或商业决策依据。

## Resources

- `references/geo-metrics.md` — 指标体系与评分标准的唯一权威来源（6 维度权重、
  0-100 评分表、等级划分、引擎矩阵要求、建议生成规则与通用建议库）。计算前必须读取。
- `scripts/geo_score.py` — 确定性评分计算器：JSON 查询明细 → 综合得分/等级/薄弱维度。
  纯标准库，无第三方依赖。
- `scripts/geo_report.py` — HTML 报告生成器：原始查询数据 + 评分结果 + 建议 → 单文件
  中文浅色主题诊断报告（内联 SVG 雷达图）。纯标准库，无第三方依赖。
