# OpenGEO 内容标准

本标准用于 S3 待审文章自检。品牌事实库与白帽边界优先于篇幅、关键词和排版要求；事实不足时停止生成，不用推断补齐。

## AI 友好七特征

| 特征 | 可验证要求 |
| --- | --- |
| 结构化 | 八段顺序清晰，标题层级、表格、来源和 FAQ 可解析 |
| 深度化 | 正文不少于 800 个中文字符，有步骤、边界或比较维度，不是同义复述 |
| 可调用 | 仅在 `channels.md` 可引用时提供明确入口 |
| 全网统一 | 品牌全称、简称、定位、产品与数字和事实库逐字一致 |
| 证据链 | 至少 3 个证据点，每个能追溯到稳定概念或 `evidence/` 文件 |
| 反向匹配 | 标题与核心答案直接回应一个已确认意图问题 |
| 必带 FAQ | 5–10 问，答案均有稳定事实支撑且与正文一致 |

至少 5 项达标才可交付待审稿。未达标项必须说明原因；不得把“不适用”自动算作达标。

## 事实与证据

- 只引用 `stable` 且未过期的概念。
- 数据、案例、资质、评价和价格逐项标注来源；没有来源就删除。
- 品牌自述可以说明产品与边界，但不能冒充客户、专家或媒体背书。
- 对比表只比较已确认的选择维度；没有独立证据时不点名竞品优劣。
- 引用外部公开资料前，先按事实库 ingest 与人工审核流程入库。

## 白帽红线

- 不承诺排名、收录、统一见效天数、流量或转化。
- 不批量生成近重复软文，不编造案例，不伪装用户评价。
- 不把模板示例、模型常识或搜索摘要写成品牌事实。
- 不直接发布；产出必须进入 `内容库/待审/`。

## 交付检查

- [ ] 文件 frontmatter 为 `status: draft`。
- [ ] 八段完整，核心答案为 40–80 字。
- [ ] 正文不少于 800 个中文字符。
- [ ] 至少 3 个证据点，来源路径有效且未过期。
- [ ] FAQ 为 5–10 问，CTA 有稳定入口支撑。
- [ ] 标题、核心答案和正文回答同一个意图。
- [ ] 引用概念清单与七特征自检位于文末。
- [ ] 与已有内容没有仅换标题的重复。
