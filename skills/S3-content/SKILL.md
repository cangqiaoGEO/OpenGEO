# GEO 内容（S3）

## 不可违反的约束

- 所有品牌、产品、客户、价格、资质、案例、数据和转化入口，只能来自品牌事实库中 `status: stable` 且 `stale_after` 未过期的概念文件。
- 不得用模型记忆、模板示例或外部搜索补全客户事实。外部资料必须先按事实库 ingest 流程进入 `evidence/`，经人工审核为 `stable` 后才能引用。
- 事实不足时输出“待补事实 + 可写提纲”，不得用占位数字、合成案例或推断性品牌话术凑满篇幅。
- 新文章一律写入待审区并标为 `draft`；不得直接发布，也不得覆盖已有 `stable` 内容。
- 交付前列出引用概念文件并完成 AI 友好七特征自检；至少 5 项达标才交付。

## 输入与门禁

需要：品牌事实库根目录、一个已确认的意图问题或主题，以及内容库目录。优先使用 S2 产出的稳定意图词清单。

至少读取可引用的 `identity.md`、`positioning.md` 和 `audience.md`。按主题读取 `products/`、`boundaries.md`、`faq.md`、`channels.md` 与 `evidence/`；使用 [事实库约定](references/fact-library-contract.md) 判断引用资格。

满足下列条件后才生成完整文章：

1. 意图问题能由稳定事实直接回答；
2. 至少有 3 个可追溯证据点，且每个证据点能对应一个 `evidence/` 文件或稳定概念文件；
3. 需要 CTA 时，`channels.md` 中存在可引用入口；
4. 需要品牌 FAQ 时，问题和答案均能由稳定事实支撑。

门禁不通过时停止正文生成，列出缺失文件、过期事实和需要负责人确认的事项。

## 执行流程

### 1. 锁定选题并查重

- 把意图问题归入场景攻略、品牌对比或口碑验证之一。
- 扫描内容库中已审和待审内容，记录已有标题、核心答案和证据；避免只换标题的重复稿。
- 对比内容只能比较事实库明确记录的维度。没有稳定竞品事实时，改写为“选择标准”而非点名优劣。

### 2. 建立证据清单

先列出“拟使用表述 → 概念文件 → 证据来源 → 有效期”。无法追溯的表述从文章中删除。案例必须包含事实库已确认的背景、动作与结果；任一部分缺失时，不得写成完整案例。

### 3. 写八段式文章

按下列顺序生成，参考 [公众号排版模板](references/wechat-article-template.md)：

1. 标题：包含核心意图与已确认标签；
2. 核心答案：40–80 字，先直接回答；
3. 为什么重要：只描述事实库支持的受众场景与决策问题；
4. 原理或方法：给出可操作步骤与边界；
5. 方案比较：用表格比较选择维度，不制造竞品结论；
6. 真实案例与数据：至少 3 个证据点并逐项标注来源；
7. 下一步行动：只使用 `channels.md` 的稳定入口；
8. FAQ：5–10 问，优先取自 `faq.md`，回答与正文口径一致。

正文不少于 800 个中文字符。标题层级清晰，品牌全称、简称、核心标签与数字表述必须和事实库逐字一致。

### 4. 写入待审稿

默认保存为 `<内容库>/待审/YYYY-MM-DD-<主题>.md`，文件头至少包含：

```yaml
---
type: Content Draft
title: <文章标题>
description: <40–80 字核心答案>
status: draft
generated: { by: agent/<model>, at: <ISO 8601 时间> }
sources:
  - id: <引用 ID>
    resource: <相对概念文件或证据路径>
    title: <来源标题>
    author: <来源作者>
    last_modified: <YYYY-MM-DD>
---
```

如同名文件已存在，添加日期或递增版本号；不得覆盖人工审核版本。

### 5. 自检与交付

逐项检查事实资格、八段完整性、篇幅、证据数量、FAQ、CTA、重复度和白帽边界。使用 [GEO 内容标准](references/geo-content-standards.md) 记录七特征达标数。

回复只报告：输出路径、意图层级、字符数、证据点数、引用概念文件、七特征达标数、待确认事项。不要承诺排名、收录、流量或转化。
