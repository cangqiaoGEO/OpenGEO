# OpenGEO 开源组织定位与产品框架
## ——基于 Profound / Scrunch / Frase / Native AI / Bluefish 五家公司的深度调研

> 调研日期：2026-08-22 ｜ 信息来源：五家官网（含 Profound 定价页）+ 企查查「品牌产品」融资数据
> 结论先行：**海外已经用 18 个月和 10 亿美元估值验证了「AI 可见度」是一个独立的营销基础设施品类；但全部是闭源 SaaS、全部围绕 ChatGPT/Gemini 系引擎、全部面向财富 500 强。中国引擎、中国信源、中国中小企业——三个空位同时存在，而且没有人做开源。OpenGEO 的定位就是这三个空位的交集：做「GEO 的开放标准与开源工具层」。**

## 三、OpenGEO 的定位

### 3.1 定位声明

> **OpenGEO 是 GEO（生成式引擎优化）的开放标准与开源工具层：用开放的品牌事实规范、开源的可见度测量与执行工具、公开的中国引擎基准，让任何企业都能「看见、理解、验证」自己在 AI 里的存在——闭源 SaaS 把「看见」卖 399 美元/月，OpenGEO 把「看见」变成公共品。**

三句话版本：
1. **对标 Profound 的功能栈，但开源、本土引擎、老板可用**；
2. **像 Linux 之于商业 Unix**：标准与工具开放，商业价值在托管、交付与服务（仓桥的 open-core）；
3. **中国市场的 GEO 基础设施由谁定义？** 我们用开源先定义，竞品跟不跟都得按这套指标说话。

### 3.2 品类命名

对外统一用：**「开放式 AI 可见度基础设施」（Open AI-Visibility Infrastructure）**；对老板用白话：**「让 AI 看见你的开源工具箱」**。

### 3.3 与仓桥的关系（open-core 边界）

| OpenGEO（开源、公共品） | 仓桥智能（商业） |
| --- | --- |
| 规范：品牌事实库 OKF L1 | 托管：OpenGEO Cloud（多品牌、周报、SSO、API） |
| 工具：诊断/七技/总控/自动化模板 | 交付：28 天陪跑、代运营、官网/独立站地基 |
| 数据：中国引擎公开基准（OpenGEO Index） | 数据：客户私有复测数据与行业深度报告 |
| 教材与课程 | 培训与认证（对标 Profound「营销工程师认证」） |
| 治理：口径宪章、白帽红线 | 品牌：「不承诺排名，只承诺复测」的交付口碑 |

## 四、产品框架（六层 + 一贯穿）

对齐海外已收敛的十个原语，补齐中国空位，保留我们的特色（事实库、复测闭环、老板可用）：

```
L5  基准层   OpenGEO Index —— 中国引擎行业可见度公开基准（对标 Profound Index）
L4  站点层   Agent-ready —— llms.txt / schema.org / 轻量 AI 页面生成（对标 Scrunch AXP）
L3  执行层   七技 + 总控 Agent + 自动化（对标 Profound Agents / Frase 闭环）
L2  洞察层   意图词与提问趋势 · 内容差距 · 竞品对标 · 爬虫/地基体检（对标 Scrunch Insights）
L1  测量层   OpenGEO Audit —— 提示词集 × 中国引擎 × 周期 → 六维分 / 声量份额 / 引用源（对标 Profound Monitor）
L0  规范层   品牌事实库 OKF —— 唯一事实源、信任分层、过期阻断（海外无对应开放规范；对标 Bluefish 叙事控制的开放版）
 ⟂  治理     口径宪章（三不承诺/三只承诺）· 白帽六红线 · 复测闭环（诊断-改进-复测）
```

### 4.1 各层产品定义与仓库规划

## 五、开源组织设计

### 5.1 组织形态

- GitHub 组织 **cangqiaoGEO** 升级为多仓库组织：`OpenGEO`（主仓/课程/规范）+ `opengeo-audit` + `opengeo-skills` + `opengeo-agentready` + `opengeo-index`；
- 许可证沿用：代码 MIT、文档 CC BY-SA 4.0；**数据（Index）CC BY 4.0**（要求署名，允许商用，最大化传播）；
- 治理：维护者小组（仓桥 + 早期贡献者）；RFC 流程（规范变更/新引擎接入/指标调整须 RFC）；**口径宪章写入 GOVERNANCE.md 作为不可协商条款**（任何「保排名」类 PR 直接关闭）。

### 5.2 社区飞轮（为什么别人会来贡献）

1. **平台实现贡献**：七技规格开放，扣子/Dify/Claude Code 的实现者提交 `<platform>-implementation`——每多一个平台，我们的标准就多一份事实上的采纳；
2. **引擎适配贡献**：新引擎（小微公测、Kimi 新版）的采集适配器；
3. **复测数据贡献**：企业匿名提交周测结果进 Index，换取行业基准对比——数据越多，Index 越有价值，这是 Profound 用资本买的东西，我们用开源换；
4. **案例贡献**：CONTRIBUTING 要求数据来源可核验——案例库本身成为反割韭菜的公共证据。

### 5.3 与闭源 SaaS 的竞合

- 不做「中国版 Profound」的正面竞争（资本与引擎数据上打不过）；做它们不做的：**开放规范 + 中国引擎 + 老板可用**；
- 海外工具进入中国必须解决封闭信源问题——OpenGEO 的公众号/视频号/小程序信源适配可以成为它们的上游依赖（标准输出者的位置）；
- 国内若出现闭源竞品，其指标口径若不与 OpenGEO 可比，在客户面前就是「自说自话」——**先定义度量，就是先定义市场**。

### 风险

- **引擎采集合规**：自动化问答采集需遵守各平台条款，优先用官方 API/企业接口，网页自动化仅限自有账号低频使用；
- **平台政策波动**：豆包抽成规则、小微公测节奏影响信源权重——Index 需带版本与日期；
- **资源**：五层六仓对一家小公司过重——**先做 L0/L1/L3（已有基础），L4/L5 靠社区**，不平行开工。
